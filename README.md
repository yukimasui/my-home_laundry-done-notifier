# laundry-done-notifier

洗濯機の終了音をESP32で検知し、MQTTを介してキオスク端末に通知するシステムです。

## 概要

洗濯機の圧電ブザー音をマイクで拾い、FFTによる周波数解析で終了を検知します。  
検知結果はMQTTで配信され、Ubuntu Server上で動作するSlintベースのキオスク端末に通知が表示されます。

## 開発のきっかけ
生産技術の業務でIoTを活用した設備の見える化に関わっており、  
市販ソフトウェアを使用してシステム構築を行っています。  
その中で、見える化としてタッチディスプレイを導入してみたはいいものの、  
3本指スワイプなどされてしまうとWindowsが見えてしまったりといった弱点がありました。  
  
そこでこれを解決する手段がないか？　と検討した結果、  
Linux + Cageという構成が良さそうという結論に至りました。  
  
会社のPCに勝手にLinuxを入れるわけにも、私物PCを勝手に持ち込むわけにも行かないので  
自宅で使用していた旧型のSurfaceを用いて  
技術検証の場として有効活用することにしました。  

またエッジデバイスという部分もIoTに関わる中で興味が湧いてきたので  
こちらの部分に関してもマイコン（ESP32）を活用、  
現場で止まらない物を作るという視点からRustを利用して開発しました。  
  
## システム構成

```
[洗濯機の圧電ブザー]
        ↓ 音を拾う
[ESP32 + マイク]
        ↓ FFT解析 → 終了音を検知
[MQTT Broker (Ubuntu Server)]
        ↓ メッセージ配信
[Kiosk端末 (Surface → Ubuntu Server / cage + Slint)]
        ↓
[通知表示]
```

## 使用技術

| レイヤ | 技術 |
|--------|------|
| マイコン | ESP32 |
| 音響解析 | FFT（周波数解析） |
| 通信 | MQTT |
| サーバー | Ubuntu Server（Surface 改造）|
| UI フレームワーク | Slint |
| キオスク化 | cage (Wayland compositor) |

## なぜこの構成にしたか

#### ESP32
- 大学時代にマイコンを趣味で触っていたので、似た感覚で触れてネットワークを利用したかった。  
    （ESP32ならマイコンに近く、WiFi、Bluetoothが乗っていてお得）
#### MQTT
- TCP通信等を利用することは業務でも行っているが、マイコンには負担が重いらしいので軽いものを使いたかった。
#### Ubuntu Server
- 古いSurfaceでは画面表示があるOSは負荷が重く、可能な限り画面表示を抑えたかった。
- Windowsは裏でどんな挙動が起きてKIOSKが破綻するのか分からない。
- Cageでデスクトップ環境を構築しなければ、そもそも変な画面に飛ぶ心配もない。
#### Rust + Slint
- 生産現場で色々導入する上でプログラム的にエラーで止まることが何よりの損失につながる。
- Rustを使うことでC/C++が潜在的に抱えていたメモリ由来のバグをほぼ取り除くことができてソフトの信頼性向上につながる。
- スペックの高いマシンで動くのは当たり前、いかに安価で熱が出ない壊れにくいマシンでUIを実現できるか試したかった。
